## 핵심 발견 (코드 분석 기반 — 외부 URL 검증은 다음 사이클)
1. **OSC 133 시맨틱 프롬프트 부재가 가장 큰 격차.** iTerm2/kitty/WezTerm는 셸이 프롬프트 시작(`A`)·명령 시작(`B`)·출력 시작(`C`)·명령 종료+exit code(`D`) 마크를 emit하면 → 터미널이 "이전/다음 프롬프트로 점프", "명령 출력만 선택/복사", "실패한 명령 강조" 같은 UX를 제공. 현재 툴킷은 precmd에서 타임스탬프만 그리고 마크는 안 emit. Ghostty는 OSC 133을 네이티브 지원하므로 **셸 측에서 마크만 추가하면 즉시 점프/스크롤백 UX가 켜짐**.
2. **Ghostty는 자체 셸 통합을 자동 주입한다.** Ghostty의 `shell-integration` 기능(zsh/bash/fish/elvish)이 이미 OSC 133·OSC 7·cursor·title 일부를 처리할 수 있음. 커스텀 `zsh-integration.zsh`가 이를 **중복·충돌**시킬 위험. precmd 타이틀 갱신(OSC 2)이 Ghostty 내장 title 기능과 겹칠 가능성 → 다음 사이클에서 `shell-integration-features` config 확인 필요.
3. **OSC 7(작업 디렉터리 리포팅) 부재.** 새 split/탭을 열 때 "현재 디렉터리 상속"이 안 됨. precmd에서 `printf '\e]7;file://%s%s\a' "$HOST" "$PWD"` 한 줄이면 split-inherit-working-directory UX 활성화.
4. **broadcast/title 훅이 precmd마다 `/tmp` stat + `tty` + `whoami` 호출** → 매 프롬프트 fork 비용. 자주 그려지는 경로이므로 캐싱 여지.

## 이 툴킷에 추가할 제안 (우선순위순)
1. **[높음] OSC 133 시맨틱 프롬프트 마크 emit** — 무엇을: precmd/preexec에서 `\e]133;A`(프롬프트)·`\e]133;B`(명령입력)·precmd 진입 시 `\e]133;D;<exit>`를 출력. 왜: Ghostty 네이티브 점프/출력선택/실패강조 UX가 공짜로 켜짐, 경쟁 터미널 대비 최대 격차 해소. 구현 파일: `zsh-integration.zsh`. 난이도: 낮음(훅 이미 존재, print 3~4줄). **단, Ghostty 내장 셸통합과 중복 안 되게 먼저 확인 필수.** Ghostty 네이티브: ✅ (터미널이 마크 소비).
2. **[높음] OSC 7 cwd 리포팅** — 새 split/탭이 현재 디렉터리를 상속. 구현: precmd에 `printf '\e]7;...'` 1줄. 난이도: 낮음. Ghostty 네이티브: ✅.
3. **[중간] Ghostty 내장 셸통합과 커스텀 스크립트 역할 분리/중복 제거** — `shell-integration-features = no-cursor,no-title` 등으로 충돌 방지하거나, 반대로 내장이 처리하는 부분(133/7)은 내장에 위임. 난이도: 중간(config + 스크립트 조정, 회귀 테스트 필요).
4. **[중간] fzf 연동 위젯** — Ctrl+R 히스토리, Ctrl+T 파일, Alt+C 디렉터리 fzf 위젯을 토킷 기능으로 등록(레지스트리+힌트). 난이도: 낮음(fzf 설치 전제). Ghostty 네이티브: ❌(셸 영역).
5. **[낮음] precmd 핫패스 최적화** — broadcast/title의 `/tmp`·`tty`·`whoami` 결과를 세션 변수로 캐싱, broadcast flag 없을 때 조기 return. 난이도: 낮음.
